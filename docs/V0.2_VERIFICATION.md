## Defects found and fixed during this work

Two real bugs were caught by the new tests and fixed before publication:

1. `packet_issues` compared manifest field labels (`- Type:`) against parsed dictionary keys
   (`Type`), so every registered asset was reported as missing its metadata fields.
2. The registered-asset set was built by slicing the manifest key with the task path prefix,
   so a correctly registered asset was simultaneously reported as unregistered.

Both are now covered by `test_approved_packet_and_asset_are_readable_from_a_fresh_clone`.

The public-fixture guard test also caught `docs/DEPLOYMENT_ZH.md` naming a real private
repository of the owner. That reference was removed; the document now refers to repositories
generically.

## Not verified here

State these plainly rather than implying coverage:

- **No second AI tool has run the v0.2 workflow end-to-end.** The automated and smoke runs
  use local repositories with a normal Git identity. Cross-tool acceptance still requires
  `onboard-check` and a handoff/read-back per tool, as described in
  `docs/PILOT_RUNBOOK.md`. The v0.2 workflow has not been exercised on a real project.
- **The source repositories in the smoke run are local bare repos, not hosted remotes.**
  Git authentication, connector permissions and hosted-remote behaviour are therefore not
  covered by that run.
- **No connector binary-upload path was exercised.** Attaching a screenshot through a chat
  connector remains unproven; the local CLI path is the supported one.
- **No efficiency claim is supported.** Time saved, token spend and defect-rate changes have
  not been measured against a baseline, so none is asserted.
- **Human UAT has not happened.** The smoke run simulated the reporter and the status
  transitions; no human tested a real build.
